# Ecommerce Product Image Studio

## 任务目标

把真实商品资料转化为一套准确、统一、可审核、可用于电商展示的产品图片。不是只抠图，也不是把一张照片交给模型自由重绘。

所有任务遵循优先级：

1. 商品真实身份与结构
2. 已核实的商品事实与卖点
3. 平台当前规则
4. 品牌一致性与商业表达
5. 场景创意和视觉美化

商品保真与事实准确不可为了画面效果牺牲。

## 适用平台与商品

- 平台：淘宝、天猫、京东、拼多多。
- 当前重点品类：家居、日用品、原木/无漆木制品。
- 架构可扩展到金属、陶瓷、玻璃、塑料、纺织品等；不同材料必须启用相应的材质保真规则。
- 不同平台、类目和广告位的图像规范可能不同，必须使用当期卖家后台或官方文档核验，不能猜尺寸或宣称一套图适配全部平台。

## 工作模式

- **标准模式（默认）**：商品主体像素锁定；AI 生成空背景、布景和非商品装饰；用合成和排版完成图片。
- **受控编辑模式**：只在用户明确要求时，对非关键区域或指定 Mask 区域进行编辑；商品身份关键区仍锁定。
- **概念创意模式**：允许模型探索商品形态或风格，仅作为内部概念稿；必须标注“非实物示意”，不得混入正式商品图。

## 阶段 1：商品素材审查

先调用/遵循 product-reference-audit：

- 列出每张照片的文件名、视角、分辨率、清晰度、遮挡和可见结构。
- 识别照片中可见的物件数量，但不要推断售卖数量、包装数量或 SKU 组合。
- 区分“照片可见事实”“用户确认事实”“未知信息”。
- 判断哪些图可用作主图、场景合成、细节裁切和规格依据。
- 输出缺失素材清单；单张图不能推断背面、底面、隐藏连接或真实侧视角。

如输入只有一张图，仍可先做同视角的白底图、背景图、排版图和局部裁切；不能伪造多角度或不存在的细节。

## 阶段 2：建立产品身份锁

遵循 product-identity-lock，创建 SKU 身份档案：

- 产品轮廓、比例、部件数量、连接关系、孔位、边缘、五金。
- 颜色、表面处理、纹理方向、自然瑕疵和可见细节。
- 参考图与每个特征的证据来源。
- 必须保留项、允许变化项、禁止变化项。
- 未确认的木种、尺寸、工艺、认证、性能与包装信息。

针对木制品必须同时遵循 wood-product-fidelity。身份锁不能只写一句 prompt；应保留原图、Mask、参考图、事实表和质检对照。

## 阶段 3：策划整套电商图片

调用/遵循 ecommerce-gallery-planner，先生成 image-plan.json。逐张图片写明：

- 图片编号、用途、平台/广告位、比例或尺寸来源。
- 核心信息、文案及证据来源。
- 主体参考图、需要补拍的照片。
- 构图、视角、背景、光线、道具、留白。
- 商品像素策略：锁定、局部编辑或概念预览。
- 生成方式、输出路径、风险和验收条件。

推荐规划模块（按类目与平台取舍，不强制固定张数）：
1. 主图/首图：真实商品主体清晰。
2. 辅图：核心特点、使用方式、套装内容。
3. 场景图：展示商品在真实使用环境中的尺度和氛围。
4. 材质细节图：木纹、端面、表面处理等真实细节。
5. 结构细节图：接缝、孔位、榫卯、五金、边缘。
6. 尺寸规格图：只用确认参数。
7. 对比/说明图：只有存在可核验对比依据时才制作。
8. 详情页模块：按购买决策顺序讲清商品，不堆砌无依据卖点。

先展示图片计划。若用户已明确要求直接执行，可先制作 1 张主图样张和 1 张场景样张，不必因非关键偏好反复询问。

## 阶段 4：素材处理与图像生成

按任务调用以下专项 Skills：

- 抠图与真实主体合成：product-cutout-composite
- 空场景与生活方式图：lifestyle-scene-composite
- 卖点、规格与详情页排版：ecommerce-infographic-detail-builder
- 品牌统一：brand-visual-system

默认的高保真管线：

1. 原始商品照片 → 分割模型只生成 Alpha Mask。
2. 检查/修正 Mask，特别是镂空、细杆、孔洞、透明或木色接近背景的边缘。
3. 商品 RGB 保留原图；禁止让分割模型的 RGB 替换商品颜色与纹理。
4. AI 生成不含商品本体的空背景；Prompt 明确 no product / no similar product / no text。
5. 通过程序合成真实商品层，必要时单独生成接触阴影层；不覆盖商品纹理。
6. 中文标题、卖点、参数、图标用程序或设计工具排版，避免图像模型生成错字。
7. 对所有生成资产保留来源、提示词、模型/工具、时间、尺寸与版本记录。

如果当前 Agent 没有可调用的图片生成工具/CLI/MCP，先输出可复用 Prompt 与合成准备，不要假装已生成图片，也不要擅自接入付费 API。

## 阶段 5：详情页与跨图一致性

- 先确定页面叙事：商品是什么 → 核心价值 → 使用场景 → 材质/结构证据 → 规格 → 包装/注意事项。
- 每个模块单独保存，最后再拼成长图；不要只交付一张不可编辑的大图。
- 同一 SKU 所有图片的商品颜色、部件数量、比例、木纹与文案事实保持一致。
- 同系列 SKU 可统一背景、光位、留白、字体和版式，但不能把一个 SKU 的独特木纹或结构复制给另一个 SKU。

## 阶段 6：质检与平台预检

必须调用/遵循：

- ecommerce-visual-qa：产品身份、结构、材质、边缘、光影、文字和整套一致性。
- marketplace-export-preflight：平台尺寸、格式、体积、比例、主图/详情槽位和文字规则。

输出 QA 报告，明确 PASS / REVIEW / FAIL 及证据。自动像素检查、尺寸检查、OCR 或视觉模型报告均不能单独证明商品完全保真；高风险图片必须人工复核。

禁止自动上传或发布。只有用户明确要求并且相关账号/工具已授权时，才进入上架环节。

## 阶段 7：交付

交付至少包括：

- 原图与产品身份档案（只读/可追溯）。
- 图片规划清单与缺失素材清单。
- 主图、辅图、场景图、细节图、规格图、详情页模块。
- 各平台导出版本（仅在规则已核验时）。
- 每张图的 QA 状态与问题。
- 可编辑的源文件/模块与最终导出文件。

文件命名建议：SKU_平台_序号_用途_版本.ext，例如 WOOD001_TAO_01_MAIN_v01.png。

## 失败处理

- 身份关键特征无法确认：暂停该图并请求补拍/确认。
- Mask 损坏结构：修 Mask，不要用生成模型补造。
- 场景透视不匹配：重新生成空背景或改用棚拍底图。
- 中文文字不准确：用程序重新排版，不让图像模型猜字。
- 平台规则不明：标记待核验，不自行填入未经证实的规格。
- QA FAIL：退回对应阶段返工，不允许静默降级为“可用”。

## 完成定义

只有当整套图的商品身份一致、事实可追溯、视觉统一、平台规格经过核验、QA 问题已处理或明确披露，才算完成。生成了图片文件不等于任务完成。
