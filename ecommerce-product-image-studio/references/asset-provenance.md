# Asset Provenance

Every production asset SHOULD have a traceable origin.

## Provenance classes

- \`SOURCE_PRODUCT_PIXEL\`: pixels from an authoritative real SKU photo.
- \`VERIFIED_CAD_3D\`: render from a verified current-SKU CAD / 3D asset.
- \`GENERATED_BACKGROUND\`: generated environment without the target product.
- \`GENERATED_PERSON\`: generated person layer.
- \`GENERATED_PROP\`: generated independent prop.
- \`PROGRAMMATIC_TEXT_GRAPHIC\`: copy, dimensions, arrows, icons, tables, or layout generated by code / design tooling.
- \`CONCEPT_ONLY\`: generated content not approved as factual SKU representation.

## Minimum provenance record

For each final image record:
- final asset path;
- SKU / variant;
- product-body provenance class;
- authoritative source path / ID;
- mask source;
- transformations;
- background source;
- person source if applicable;
- text / graphic source;
- generation tool / model where relevant;
- prompt / parameters where relevant;
- QA status.

## Product-body rule

If the product body is based on an authoritative photo, provenance SHOULD remain \`SOURCE_PRODUCT_PIXEL\`.

If the product was regenerated by a model, it cannot be labeled \`SOURCE_PRODUCT_PIXEL\` even when the output looks nearly identical.

## Generated concepts

Generated lookalikes MAY be retained for:
- creative exploration;
- composition ideation;
- storyboard;
- non-factual concept preview.

They MUST NOT silently replace SKU production assets.
